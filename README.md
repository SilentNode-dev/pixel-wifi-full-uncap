# Pixel Wi-Fi 6E/7 (6GHz) & Max TX Power / No-SAR Unlock

> **Аппаратный и системный анлок Wi-Fi на Google Pixel 8 / Pixel 8 Pro (Tensor G3 / Broadcom BCM4398): полная разблокировка диапазона 6 ГГц (Wi-Fi 6E / Wi-Fi 7, 59 каналов), снятие ограничений мощности (переход на стандарты FCC до 1000 мВт / 30 dBm) и полное отключение троттлинга мощности SAR (Specific Absorption Rate).**
> 
> *Совместимо с Android 14, 15, 16, 17+ (протестировано на Android 17 сборки `CP4A.261105.040.A1`).*

---

## 📌 Введение и суть проблемы

В Google Pixel 8 Pro установлен передовой трёхдиапазонный радиочип **Broadcom BCM4398** с поддержкой стандарта **Wi-Fi 7 (802.11be)**, каналов шириной до 320 МГц и модуляции 4096-QAM. 

Однако при использовании смартфона в России и ряде других стран пользователь сталкивается с тремя искусственными барьерами:

1. **Блокировка 6 ГГц (Wi-Fi 6E / Wi-Fi 7)**:
   - В РФ диапазон 6 ГГц (полоса **5945–6425 МГц**, каналы 1–85) **официально разрешён** решением ГКРЧ № 22-65-01 от 23.12.2022 для безлицензионного использования внутри помещений (LPI / VLP).
   - Но как только в смартфон вставляется российская SIM-карта (MCC `250`), служба `TelephonyManager` передаёт код страны `RU` в `WifiCountryCode`.
   - В региональных таблицах Broadcom CLM (Country Locale Matrix) для региона `RU` диапазон 6 ГГц попросту выключен:
     ```
     mDriverCountryCode: RU
     SupportedChannelListIn6g = [] (0 каналов!)
     ```
   - Смартфон становится полностью «слепым» к сетям Wi-Fi 6E и Wi-Fi 7 на частоте 6 ГГц.

2. **Ограничение мощности передачи (EIRP Limits)**:
   - В европейских и российских профилях мощность передатчика ограничена нормами CE: **100 мВт (20 dBm)** на 2.4 ГГц и **200 мВт (23 dBm)** на 5 ГГц.
   - В то же время по американским нормам FCC чип способен легально выдавать до **1000 мВт (30 dBm)** — это в **5–10 раз мощнее**, что критично для пробиваемости стен и стабильности гигабитного линка.

3. **Динамический SAR Backoff (глушение мощности телом)**:
   - При удержании телефона в руке, разговоре или работе сотового модема встроенный Context Hub (CHRE) рапортует сценарии SAR (`tx_power_mode 3`).
   - Драйвер считывает калибровочные таблицы `/vendor/firmware/bcmdhd_txcap.blob` и принудительно снижает мощность Wi-Fi на **6–10 dB** (падение реальной мощности излучения в 4–10 раз).

## 🔬 Реверс-инжиниринг прошивки Broadcom BCM4398

Для устранения этих ограничений без повреждения системного раздела `/vendor` было проведено исследование низкоуровневых компонентов `bcmdhd4398`:

### 1. Формат блоба `bcmdhd_txcap.blob`
Файл `/vendor/firmware/bcmdhd_txcap.blob_4398_d0` представляет собой бинарный контейнер с собственной проприетарной структурой:
```
[Заголовок BLOB: 60 байт]
├── 0x00..0x03: Сигнатура 'BLOB'
├── 0x04..0x07: Размер заголовка (0x3C = 60 байт)
├── 0x08..0x0B: CRC32 заголовка (хэш байт 0x0C..0x3C)
├── 0x0C..0x17: Версия, число секций (2)
├── 0x18..0x23: Секция 1: Смещение (60), Длина (2422), CRC32 полезной нагрузки
└── 0x24..0x3B: Секция 2: Смещение (2482), Длина (4), CRC32 секции 2
```

### 2. Таблицы мощности (Tag 7)
Внутри секции 1 содержатся **180 таблиц лимитов мощности** по всем сценариям SAR и регуляторным зонам.
- Каждая таблица начинается с тега `0x07`.
- Значения задаются в четвертях дБм (qdBm).
- При срабатывании SAR значения падают до `0x34` (13 dBm), `0x3a` (14.5 dBm) или `0x4c` (19 dBm).
- Значение **`0x7F`** (127 decimal = 31.75 dBm) зарезервировано как **максимальный потолок без троттлинга (Unthrottled)**.

## 🛠 Архитектура модуля

Модуль действует полностью **systemless** (не модифицируя read-only раздел vendor на накопителе):

1. **Патчинг таблиц SAR (`bcmdhd_txcap.blob_4398_d0` и `_c0`)**:
   - Все 180 таблиц мощности модифицированы: каждое значение заменено на `0x7F`.
   - Двухуровневый CRC32 (CRC32 полезной нагрузки секции 1 и CRC32 заголовка) пересчитан с нуля. Прошивка принимает блоб как 100% валидный заводской файл.
2. **Отключение SAR в NVRAM (`bcmdhd.cal_NA` / `bcmdhd.cal_ROW`)**:
   - Параметр динамического SAR переведён в неактивный режим: `dynsar_fcc_rev=0`.
3. **Раннее монтирование (`post-fs-data.sh`)**:
   - Модифицированные файлы монтируются через `mount --bind` прямо поверх оригиналов в `/vendor/firmware/` с соблюдением SELinux-контекста `u:object_r:vendor_fw_file:s0`.
4. **Фиксация FCC-профиля (`service.sh`)**:
   - При старте системы скрипт однократно вызывает:
     ```sh
     cmd wifi force-country-code enabled US
     ```
   - За счёт этого Android выставляет `mOverrideCountryCode: US`, который на уровне AOSP обладает высшим приоритетом и **полностью игнорирует код RU от российских SIM-карт**.

## 📥 Установка

1. Скачайте архив [`Pixel_Wi-Fi_Full_Uncap.zip`](./Pixel_Wi-Fi_Full_Uncap.zip).
2. Откройте **KernelSU**, **Magisk** или **APatch**.
3. Перейдите в раздел **Модули** -> **Установить из хранилища**.
4. Выберите скачанный архив и дождитесь завершения установки.
5. Перезагрузите устройство.

## 📁 Структура репозитория

```
├── Pixel_Wi-Fi_Full_Uncap.zip               # Готовый архив модуля для прошивки
├── module.prop                              # Описание модуля для Magisk/KernelSU
├── customize.sh                             # Скрипт установки
├── post-fs-data.sh                          # Systemless bind-mount пропатченных блобов
├── service.sh                               # Автофиксация региона US при загрузке
├── build.sh                                 # Скрипт повторной сборки архива
└── vendor/
    └── firmware/
        ├── bcmdhd_txcap.blob_4398_d0        # Пропатченные таблицы SAR (0x7F) с валидным CRC32
        ├── bcmdhd_txcap.blob_4398_c0        # Пропатченные таблицы SAR (0x7F) с валидным CRC32
        ├── bcmdhd.cal_NA                    # Калибровки NVRAM с отключенным dynsar
        └── bcmdhd.cal_ROW                   # Калибровки NVRAM с отключенным dynsar
```
